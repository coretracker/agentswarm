# Execution Plan: Teams with User-Level Authorization

## Goal

Add one optional team per user. Teams widen access to a teammate's tasks only when the viewer also has the relevant user-level task scope and repository access.

## Delivered

- Added PostgreSQL team storage, CRUD APIs, and nullable user team assignment.
- Added shared team-aware task access for REST, MCP, terminals, linked workspaces, and realtime events.
- Added Settings team management, user team assignment/display, documentation, and focused coverage.

## Decisions

- Users have zero or one team; existing tasks follow the owner's current team.
- Team visibility additionally requires repository access, while owners keep access to their own tasks.
- Teams have names only; roles and permissions remain user-level.
